# OpenZeppelin Relayer 1.9.0 release report

Relayer Failure Lab, 2 November 2026. Maintained by Nonceworks. Not affiliated with OpenZeppelin.

Sources: [results/v1.9.0.json](https://github.com/zachsplat/relayer-failure-lab/blob/main/results/v1.9.0.json) and the [lab README](https://github.com/zachsplat/relayer-failure-lab#readme). Every lab number below comes from one of them.

## What we ran

- Image: `openzeppelin/openzeppelin-relayer:v1.9.0`, pinned by digest `sha256:3ceb3986c636cd41c8eadc685a50c8e3df643206f039485694e41c6922d47fae`. The container reported `service_version` 1.9.0.
- Run: the lab's release workflow on GitHub Actions, started by hand (`workflow_dispatch`) at lab commit `0c328c3`: https://github.com/zachsplat/relayer-failure-lab/actions/runs/41385667287. Results committed 2026-11-02 04:18 UTC.
- Setup: each scenario runs the official image against a local anvil chain, injects the fault its issue describes, and records whether the issue **reproduces** or is **fixed**. Anything else is inconclusive and fails CI.

## Results

| Issue | What goes wrong in production | Outcome on 1.9.0 | Scenario time |
|---|---|---|---|
| [#817](https://github.com/OpenZeppelin/openzeppelin-relayer/issues/817) | A mined transaction is reported Failed, so an app that retries failed payouts pays twice | reproduces | 249 s |
| [#912](https://github.com/OpenZeppelin/openzeppelin-relayer/issues/912) | `whitelist_receivers` does not apply to the sign endpoints | reproduces | 53 s |
| [#843](https://github.com/OpenZeppelin/openzeppelin-relayer/issues/843) | Transactions jam behind `nonce too high` after a provider outage | reproduces | 866 s |
| [#808](https://github.com/OpenZeppelin/openzeppelin-relayer/issues/808) | A transaction priced at `gas_price_cap` during a gas spike is never resent | reproduces | 1,346 s |

### #817: mined transfer finalised as Failed

The proxy answered `null` to all 17 receipt requests. Anvil mined the transfer with status 1 in block 21, 10 seconds after submission. 190 seconds after submission the Relayer finalised it as `failed`, with the reason "Nonce 0 consumed externally (on-chain nonce: 1). No matching transaction hash found on-chain."

### #912: sign endpoint skips the receiver policy

`whitelist_receivers` allowed account #1 only. A transaction to account #2 was refused with HTTP 400 ("Transaction target address is not whitelisted"). `/sign-typed-data` then returned HTTP 200 for an EIP-3009 authorization to account #2. Account #2 submitted `transferWithAuthorization`, it succeeded, and the Relayer address's 1,000 test tokens moved to account #2.

### #843: nonce jam after a send outage

One transfer every 2 seconds for 12 minutes, 360 in total, with HTTP 503 on every broadcast for 60 seconds. Drift (the Relayer's next nonce minus the on-chain nonce) was 33 in every sample of the last 5 minutes of intake; the scenario counts a reproduction when drift never falls below 10 in that window. The proxy rejected 1,300 broadcasts with `nonce too high`. All 360 transfers confirmed in the end, and the queue emptied 90 seconds after intake stopped.

### #808: stuck at the gas price cap

`gas_price_cap` was 0.8 gwei and the first broadcast went out at that cap. After the spike the base fee returned to 0.1 gwei (one eighth of the cap) for 1,204 seconds. The transfer was still `submitted`, the sender's nonce had not moved, and the Relayer made no broadcast in that time. Its log shows "bumped gas price does not meet minimum requirement, skipping resubmission" 93 times.

## A fix the lab detects: PR #862

[PR #862](https://github.com/OpenZeppelin/openzeppelin-relayer/pull/862), OpenZeppelin's open fix for #843, was rebased onto v1.9.0 and built locally. On a network carrying the `arbitrum-based` tag, the #843 scenario showed a drift of 0 in every sample of the last 5 minutes and an empty queue 30 seconds after intake stopped: **fixed** ([result](https://github.com/zachsplat/relayer-failure-lab/blob/main/results/branches/pr862-on-v1.9.0-843.json)). The README's comparison run of stock v1.9.0 showed a drift of 39 to 44, and the CI run above showed 33.

#862 only acts on networks tagged `arbitrum-based`. The same build on an untagged network still reproduced, with a drift of 39 to 40 ([result](https://github.com/zachsplat/relayer-failure-lab/blob/main/results/branches/pr862-on-v1.9.0-843-untagged.json)). Operators who adopt #862 should check that their network definition carries the tag.

## How to reproduce

Requirements: Docker with Compose v2 and Python 3.10 or later.

```bash
git clone https://github.com/zachsplat/relayer-failure-lab && cd relayer-failure-lab
python3 lab.py run --version v1.9.0 \
  --image openzeppelin/openzeppelin-relayer:v1.9.0@sha256:3ceb3986c636cd41c8eadc685a50c8e3df643206f039485694e41c6922d47fae
python3 lab.py run --scenario 912        # one scenario
python3 lab.py run --expect              # also fail if an outcome differs from results/<version>.json
```

To test a fix branch, build its image and pass it with `--version`, `--image` and `--allow-unpinned` (README, "Run it"). In parallel the whole suite takes as long as #808, about 22 minutes on our test machine.

## The next release
